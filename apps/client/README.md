# Flutter survey client (pre-release)

Implemented source covers Riverpod bootstrap, Persian RTL / English shell, themes,
authentication, account-isolated local SQLite records/outbox/revisions, project and
customer forms, rooms, explicit-coordinate walls, openings/obstacles, plan/elevation
previews, measurement edits, session undo/redo, photo capture/gallery, online sketch
candidate review with source regions, approval controls, export downloads and Telegram.
These are not a claim of full platform acceptance. See `../../docs/project-status.md`.

## Build toolchain
Install current stable Flutter with Android SDK and Java 17. From repository root:

```sh
bash scripts/bootstrap-client.sh
cd apps/client
flutter analyze --no-fatal-infos
flutter test --timeout 30s
flutter run -d chrome
flutter build web --release
flutter build apk --debug --dart-define=API_BASE_URL=https://YOUR_API/api/v1/
flutter build appbundle --release --dart-define=API_BASE_URL=https://YOUR_API/api/v1/
```

Platform runners are generated by `flutter create`, not maintained as hand-written
Gradle scaffolds. Bootstrap also installs the SQLite browser WASM/worker assets and
adds Android Internet permission. Run it before building. CI executes these same
steps and must pass before release. Generated Android release configuration uses
Flutter's default development signing: configure owner signing before distribution.

Web defaults to same-origin `/api/v1/`. Reverse proxy it to FastAPI; never put API
keys in compile-time variables. Android requires an explicit HTTPS API base URL.
CI's `.invalid` endpoint intentionally prevents accidental use of a real production
service: rebuild with your authorized host for connected-device testing.

## Honest limitations
- Device-local guest records are separate from signed-in account records; no implicit
  transfer. Account-local capture works after secure session restoration.
- Sync is manually initiated; it stops dependent writes on conflicts, preserving both
  snapshots. Keep-server or explicit keep-local rebasing is available. Full merge UI,
  tombstones, deleted-record propagation and photo upload sync are not complete.
- Photos are stored locally. Online analysis sends the selected image only after a
  user action. Region overlays are candidates, not inferred room geometry. Crop,
  perspective correction, OCR preprocessing and voice recording remain open.
- All dimension forms use integer mm. Wall endpoints are explicitly entered; moving
  a wall is done by coordinate editing, not freehand scaling or drag snapping.
- Undo/redo creates revisions and resets approval; session stacks are not persisted.
- SQLite records and photos are not encrypted. Refresh tokens use secure storage;
  browser storage security depends on HTTPS/origin isolation and device security.
- Some diagnostic strings and technical element kinds are not translated yet.
- Server export currently selects the first room; complete multi-room packages and
  physical print calibration remain open. Do not fabricate from a local preview.
