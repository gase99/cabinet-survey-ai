# راه‌اندازی شخصی سرور روی همان گوشی (آزمایشی)

این روش فقط برای استفادهٔ شخصی و **حالت توسعه** است، نه سرور عمومی یا محیط عملیاتی. سرور روی `127.0.0.1` همان گوشی گوش می‌دهد؛ برنامه و Termux باید روی یک دستگاه باشند. تا وقتی Termux و سرور فعال نباشند ورود و همگام‌سازی ممکن نیست؛ برداشت آفلاین برنامه جداگانه است.

> **محدودیت مهم:** نصب وابستگی‌های قفل‌شده روی Termux/Android هنوز روی دستگاه واقعی آزمایش نشده و ممکن است کامل نشود. به‌ویژه `psycopg-binary==3.3.9` برای محیط بومی Termux ممکن است wheel سازگار نداشته باشد؛ در بررسی Linux با هدف `linux_aarch64` چنین wheelی پیدا نشد (این آزمایش خود Termux نیست). فایل قفل نسخه‌های باینری دیگری هم دارد. تا نصب کامل و آزمون روی دستگاه انجام نشده، این دستورالعمل تضمین اجرا نیست. اگر pip خطا داد، خطا را نگه دارید؛ قفل را بدون بررسی تغییر ندهید و تصور نکنید سرور نصب شده است.

## ۱. نصب Termux و دریافت پروژه

1. Termux را از [F-Droid](https://f-droid.org/packages/com.termux/) نصب کنید، نه نسخهٔ قدیمی Play Store. Termux را باز کنید و بسته‌ها را به‌روز کنید:

   ```sh
   pkg update && pkg upgrade
   pkg install git python clang make pkg-config rust openssl libffi libjpeg-turbo libpng libwebp freetype libxml2 libxslt zlib sqlite
   ```

   نام/دسترس‌پذیری بسته‌ها به نسخهٔ مخزن Termux بستگی دارد؛ اگر `pkg` بسته‌ای را پیدا نکرد، نصب متوقف است و باید نام بسته در مخزن همان نسخه بررسی شود.
2. مخزن را بگیرید و نسخهٔ مورد نظر را checkout کنید (برای شاخهٔ کاری نام آن را به‌جای `BRANCH` بنویسید):

   ```sh
   git clone https://github.com/gase99/cabinet-survey-ai.git
   cd cabinet-survey-ai
   git checkout BRANCH
   python -m venv .venv
   . .venv/bin/activate
   python -m pip install --upgrade setuptools wheel
   python -m pip install -r backend/requirements.lock
   ```

   فایل lock با Python 3.11 تولید شده است؛ نسخهٔ Python کنونی Termux ممکن است متفاوت و ناسازگار باشد. بستهٔ `python` خود pip را فراهم می‌کند؛ در Termux از به‌روزرسانی خود pip با `pip install --upgrade pip` پرهیز کنید.

### مشکلات احتمالی ساخت بسته‌ها

- `pillow`: کامپایلر و کتابخانه‌های JPEG، PNG، WebP، freetype و zlib لازم‌اند. `reportlab` و `rl-renderpm` نیز افزونهٔ C دارند؛ ساخت backend رندر یا استفاده از آن روی Android ممکن است شکست بخورد.
- `cryptography`: به Rust، clang، OpenSSL و libffi نیاز دارد؛ `cffi` نیز libffi و کامپایلر می‌خواهد. Rust یا ابزار ساختِ سازگار لزوماً برای همهٔ معماری‌ها موجود نیست.
- `pydantic-core`، `python-bidi` و `watchfiles` افزونهٔ Rust دارند؛ علاوه بر rust/cargo ممکن است ابزار یا وابستگی‌های ساخت آنها با Android ناسازگار باشند. `lxml` به libxml2 و libxslt و `pyyaml`، `bcrypt` و `httptools` به ابزار ساخت نیاز دارند.
- `psycopg[binary]` در lock به `psycopg-binary` مقید است؛ نبود wheel مناسب باعث خطای `No matching distribution found` می‌شود، حتی اگر این راهنما از SQLite استفاده کند. `uvloop` نیز ممکن است روی Android قابل ساخت/اجرا نباشد. در چنین مواردی نصب **همان lock** متوقف می‌شود؛ حذف یا جایگزینی بسته‌ها بدون تولید و آزمون lock جدید راه‌حل تأییدشده نیست.

## ۲. جلوگیری از خوابیدن و اجرای نخست

در تنظیمات Android برای Termux محدودیت مصرف باتری را خاموش کنید (Battery → Unrestricted یا معادل گوشی). سپس در Termux:

```sh
cd ~/cabinet-survey-ai
. .venv/bin/activate
termux-wake-lock
./scripts/run-personal-server.sh
```

اجرای اول فایل `var/data/personal/.env` را با رمزهای تصادفی و دسترسی خصوصی می‌سازد، مهاجرت‌های Alembic را اعمال و سرور را اجرا می‌کند. فایل موجود بازنویسی نمی‌شود. پایگاه SQLite در `var/data/personal/cabinet_survey.db` است. این اسکریپت مستقل از `.env` استقرار، همواره حالت development و SQLite را تحمیل می‌کند و به `127.0.0.1:8000` محدود است. پیام شروع را بررسی کنید. برای توقف **Ctrl+C**؛ بعد از توقف برای آزاد کردن wake lock دستور `termux-wake-unlock` را اجرا کنید. پس از بستن یا کشته‌شدن Termux باید سرور را دوباره اجرا کنید. محدودیت باتری و wake lock تضمین نمی‌کنند Android هرگز پردازه را نکشد.

## ۳. ساخت و نصب APK

در GitHub مخزن، Actions → **personal-debug-apk** → Run workflow را باز کنید، شاخهٔ حاوی تغییر را انتخاب کنید و `api_base_url` را روی `http://127.0.0.1:8000/api/v1/` بگذارید. GitHub اجرای دستی را تنها زمانی نشان می‌دهد که فایل workflow در شاخهٔ پیش‌فرض مخزن موجود باشد؛ تا قبل از ادغام/انتشار workflow در شاخهٔ پیش‌فرض، دکمه ممکن است در دسترس نباشد. بعد از موفقیت، در صفحهٔ همان اجرا از بخش Artifacts فایل `personal-debug-apk` را دانلود، ZIP را باز و `app-debug.apk` را نصب کنید؛ در صورت درخواست Android، نصب از آن منبع را اجازه دهید. این APK نسخهٔ debug است، نه AAB انتشار.

URL با همان تابع اعتبارسنجی برنامه بررسی می‌شود؛ آدرس HTTPS معتبر یا HTTP در debug از نظر تابع مجاز است، اما سیاست امنیت شبکهٔ Android برای HTTP فقط `127.0.0.1`، `localhost` و `10.0.2.2` را اجازه می‌دهد. `10.0.2.2` برای شبیه‌ساز است و در گوشی واقعی به سرور Termux اشاره نمی‌کند. URL و APK راز نیستند؛ هیچ نام کاربری/رمزی در URL وارد نکنید.

**به‌روزرسانی و امضا:** APKهای debug اجراهای مختلف CI ممکن است با کلیدهای متفاوت امضا شوند. Android نصب روی نسخهٔ با امضای متفاوت را رد می‌کند و در این حالت باید نسخهٔ قبلی حذف شود. **حذف برنامه داده‌های محلی، عکس‌ها و تغییرات همگام‌نشده را از بین می‌برد.** قبل از حذف، وارد حساب شوید، Sync کنید و رفع تعارض و رسیدن داده‌ها به سرور را بررسی کنید؛ از فایل‌های سرور هم نسخهٔ پشتیبان بگیرید. داده‌های صرفاً محلی/آفلاین یا عکس‌هایی که به سرور نرسیده‌اند با نصب مجدد بازنمی‌گردند.

## ۴. ساخت حساب و ورود

سرور را در Termux روشن نگه دارید و APK را باز کنید. در صفحهٔ ورود، **Register / ثبت‌نام** را بزنید، نام، ایمیل و رمز را وارد و Save / ذخیره را انتخاب کنید. برای ثبت‌نام تأیید ایمیل ارسال نمی‌شود؛ ایمیل معتبر با قالب درست را به‌عنوان شناسه نگه دارید. رمز باید حداقل ۸ و حداکثر ۱۲۸ کاراکتر باشد؛ یک رمز قوی و منحصربه‌فرد انتخاب کنید (سرور پیچیدگی بیشتر از طول را الزام نمی‌کند). پس از ثبت‌نام برنامه ورود را انجام می‌دهد. اگر پیام عدم دسترسی دیدید، اجرای سرور و URL نمایش‌داده‌شده را بررسی کنید.

## ۵. پشتیبان‌گیری و بازیابی

ابتدا سرور را با Ctrl+C متوقف کنید تا فایل SQLite و فایل‌های وابسته ثابت باشند. از پوشهٔ شخصی کامل (پایگاه، `.env`، عکس‌های سرور و خروجی‌ها) در مکانی خصوصی نسخه بگیرید؛ فقط کپی پایگاه برای بازگردانی همهٔ فایل‌ها و کلیدها کافی نیست:

```sh
cd ~/cabinet-survey-ai
mkdir -p "$HOME/personal-backup"
cp -a var/data/personal/. "$HOME/personal-backup/"
```

نسخهٔ پشتیبان حاوی اطلاعات مشتری و کلیدهای محرمانه است؛ آن را رمزگذاری و خارج از گوشی در جای امن نگه دارید و به اشتراک نگذارید. این کپی داخل گوشی در صورت خرابی/حذف Termux از بین می‌رود. برای بازیابی، پس از توقف سرور و گرفتن نسخهٔ ایمن از وضعیت فعلی، محتوای پشتیبان کامل را با همان ساختار به `var/data/personal/` برگردانید و سرور را دوباره اجرا کنید. مسیرهای فایل ذخیره‌شده در پایگاه ممکن است به مسیر نصب قبلی وابسته باشند؛ بازیابی روی دستگاه یا مسیر دیگر نیازمند بررسی جداگانه است. پشتیبان سرور شامل تغییرات هنوز همگام‌نشدهٔ برنامه نیست.

## هشدار امنیتی

حالت توسعه و HTTP برای استفادهٔ عمومی مناسب نیستند. برنامه‌های دیگر روی همان گوشی ممکن است به سرویس loopback دسترسی داشته باشند؛ از قفل دستگاه و رمز قوی استفاده کنید و گوشی را قابل اعتماد فرض کنید. این راه‌اندازی بازیابی رمز مبتنی بر ایمیل یا مدیریت سرور عمومی ارائه نمی‌کند. تغییر تنظیم شبکه برای دسترسی بیرونی را با این اسکریپت انجام ندهید.
