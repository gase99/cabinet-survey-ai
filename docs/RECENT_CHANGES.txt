--------------------------------------------------------------------------------
1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Cabinet Survey AI is a pre-release surveying tool for kitchen/cabinet work. A
surveyor captures a room's walls, heights and architectural elements (doors,
windows, pipes, electrical points, columns, beams, recesses, protrusions) through
three input channels - photos/sketches, spoken measurements, and manual numeric
entry. All values are integer millimetres internally. AI output is treated
strictly as untrusted proposals: every measurement requires explicit human
confirmation before it is approved, and the final 2D plan plus wall elevations
are generated by a deterministic geometry engine, never by an AI model.

The product is Android-only at the current stage. Web support was explicitly
cancelled by the owner (ADR-006) and must not be reintroduced.

--------------------------------------------------------------------------------
2. CURRENT PROJECT ARCHITECTURE
--------------------------------------------------------------------------------
- apps/client            Flutter/Dart Android client (native SQLite via sqflite,
                         transactional outbox, manual sync, confirm-first forms,
                         sketch review, voice intake screen, SAF document saving).
- backend/app            FastAPI service: projects/rooms/walls/elements, auth,
                         deterministic geometry engine, SVG->PDF/PNG export,
                         AI provider abstractions (vision, text, speech).
- services/telegram-bot  Independent Telegram webhook/delivery worker on
                         owner-controlled compute (ADR-005).
- packages               Shared contracts/geometry.
- docs                   Product and engineering documentation (Persian and
                         English), architecture decision records (ADR-001..007).
- deploy                 Compose deployment, nginx gateway.
- test_fixtures          Anonymized inputs and golden geometry outputs.

Key architectural decisions in force:
- Android-only client; web cancelled (ADR-006).
- Provider-independent AI integrations; credentials stay server-side.
- Deterministic geometry is the only authority for drawing coordinates.
- No measurement becomes approved without explicit user confirmation.
- Unknown measurements stay unknown; dimensions are never inferred from pixels.
- Internal unit: integer millimetres everywhere; conversion only at UI/API
  boundaries.
- Local-first direction adopted (ADR-007): project data stays on-device, no
  automatic cross-device sync, permanent storage and encryption at rest are
  later phases of the same decision set.

3. RECENT IMPLEMENTED CHANGES
--------------------------------------------------------------------------------
The most recent work phase (commits c813b7b, fbb2dd6, 69b4429, e34b62c on the
PR #2 branch) implemented phase 1 of the approved voice-measurement decision set
(ADR-007):

Backend:
- New deterministic conversational Persian measurement parser
  (backend/app/domain/spoken_measurements.py). Understands Persian word
  numerals, compound spoken measurements ("سه متر و بیست سانتی‌متر" -> 3200 mm),
  scale words ("سه هزار و دویست میلی‌متر"), decimal digits ("۳٫۲ متر" -> 3200),
  correction intent ("نه، طول دیوار ... بود" -> intent=correction), per-value
  kind inference (wall_length, wall_height, base/wall cabinet depth, window,
  door, pipes, electrical, column, beam) and elided tail units ("سه متر و بیست"
  -> flagged with elided_tail_unit for user confirmation). It never invents
  values, never produces coordinates, and marks every observation
  needs_review=true.
- New parse_measurements_any() merge in backend/app/ai/provider.py combining
  the existing labeled parser ("دیوار A: 3200 mm") with the spoken parser;
  labeled evidence wins on overlapping spans; labeled "no structure" noise is
  suppressed when spoken observations exist.
- /ai/parse-text now uses the merged parser; /ai/transcription text path too.

Client (Flutter):
- Api.parseText(): form-encoded POST to ai/parse-text with bearer token.
- New domain/voice.dart: pure client-side mapping of extraction payloads into
  proposals; same-kind conflicting values are flagged and displayed, never
  auto-resolved; cabinet depths are display-only in this phase.
- New features/voice_intake.dart screen: typed/pasted transcript analysis,
  proposal cards with the exact spoken source quote, clarification questions,
  disclaimer, and per-proposal Apply.
- features/workspace.dart: Apply prefills the existing confirm-first wall form.
  A voice-sourced new wall is stored with source=voice_ai and
  review_status=needs_review; corrections go through the normal edit path so
  previous observations remain in revision history. Undo/redo bookkeeping
  unchanged.
- Persian/English localization strings added (lib/core/l10n.dart).

Exports (bug fix, previously reported):
- Multi-room export: PDF/PNG export now includes EVERY room of a project
  (backend/app/api/v1/exports.py + export_service.py render_views_pdf/png over
  explicit view lists). Previously only the first room was exported. A geometry
  error or an unapproved measurement in ANY included room now fails the whole
  export with a per-room labeled error (400 invalid geometry / 409 approval
  required), including the room label.

Documentation:
- ADR-007 added to docs/decisions.md (local-first, three input methods, AI
  proposals -> structured data, human confirmation, revision history, deferred
  on-device audio capture).
- docs/voice-phase-report-fa.md: detailed Persian implementation report.
- docs/project-status.md, CHANGELOG.md, docs/local-development.md and
  .env.example updated (STT configuration; no real credentials included).

5. BACKEND CHANGES
--------------------------------------------------------------------------------
- Speech-to-text abstraction (backend/app/ai/speech.py): STTProvider protocol
  plus OpenAICompatibleSTT implementation (HTTPS-only base URL, /audio/
  transcriptions, bearer key, language hint fa/en). get_stt_provider() fails
  closed with a clear, user-actionable message when STT is unconfigured; the
  typed-text path remains fully functional.
- /ai/transcription audio path completed: validated_audio_upload() sniffs the
  audio container signature (RIFF/WAVE, OggS, MP3 ID3/frame sync, WebM EBML,
  MP4 ftyp), enforces AUDIO_MAX_BYTES (default 10 MiB), rejects wrong MIME
  (415) and signature mismatch (422); success responses carry
  external_transmission=true and a user-facing notice that audio was sent to
  the configured external service.
- New settings in backend/app/core/config.py: stt_provider (default
  "disabled"), stt_base_url, stt_api_key, stt_model, audio_max_bytes.
- Export service refactor: render_views_pdf()/render_views_png() take explicit
  (title, svg) view lists; the legacy single-room functions are preserved as
  back-compatible wrappers.

7. SECURITY AND CONFIGURATION IMPROVEMENTS
--------------------------------------------------------------------------------
Recent phase:
- Audio uploads are content-sniffed and size-bounded; declared MIME is never
  trusted alone.
- External-transmission disclosure for speech recognition is part of the API
  response contract, supporting informed consent before audio leaves the
  system.
- STT endpoint must be HTTPS; plaintext HTTP base URLs are rejected.
- STT credentials are server-side only (.env / environment); the Flutter
  client contains no secrets, and .env.example only carries placeholders.
- No changes to JWT/session handling, upload validation for images/PDF, or
  provider key storage in this phase.

Standing security posture (documented previously, still open):
- SQLite and stored photos are NOT encrypted at rest yet; SQLCipher + Android
  Keystore is the planned later phase.
- Release builds enforce HTTPS API endpoints; emulator HTTP is restricted to
  debug/profile builds.
- AI/Telegram credentials remain exclusively on the backend/owner compute.
