## 5. Security findings

### 5.1 Verified strengths

- Revocable rotating sessions; refresh tokens stored hashed.
- Authentication throttling backed by the database.
- AI provider keys encrypted at rest with Fernet.
- Upload size bounds and MIME validation.
- SVG label content escaped.
- Telegram worker validates required secrets at startup.
- Containers run as non-root.
- Production configuration checks fail closed.

### 5.2 Secret scan

The branch and `main` were searched for bot-token patterns, `sk-` keys, AWS key patterns, private-key headers, and `ghp_` tokens. **No secrets were found** in source, `.env.example`, or the searched history. No credentials are reproduced in this report.

### 5.3 Confirmed weaknesses and open findings

- `docs/security-review.md` records findings AUTH-01 through TG-03 as open, with stated remaining limits.
- Local SQLite database and stored photos are unencrypted.
- Web refresh token is held in browser secure storage.
- No malware scanning on uploads.
- No TLS bundled; no trusted-proxy configuration despite a code comment implying one.
- Fixed-window quota permits boundary bursts.
- No structured logging, readiness probe, or database health check in the health endpoint.
- No dependency lockfiles; backend has no lint or type-check gate.
- `ElementUpdate.height_mm`, `sill_mm`, and `depth_mm` lack `strict=True` (unlike `ElementCreate`), permitting string-to-integer coercion; not covered by tests.
- REST `PUT` endpoints perform no optimistic-concurrency check; only sync enforces `base_version`.
- SQLite foreign keys are not enabled.

## 6. Release blockers (ranked)

1. **Client CI is red.** Production browser acceptance times out on `networkidle`. PR #1 cannot merge in this state, and Android artifacts are consequently unverified.
2. **Process governance drift.** The branch rewrites `AGENTS.md` and `docs/development-roadmap.md` to authorize autonomous progression through roadmap phases, removing the phase-boundary approval gate. This contradicts the approved workflow and should be reverted or explicitly approved.
3. **Approval integrity.** Manual wall/element creation is auto-approved (`review_status="approved"` for `source="manual"`); `incomplete` is never assigned; approved measurements are edited in place. Exports can therefore include approved elements with unknown height or sill.
4. **No audit trail.** Sync edits, approvals, and conflict resolutions emit no server-side audit events, and there is no revision/history table for approved measurements.
5. **Data-model gaps.** No `WallConnection`, `ReviewDecision`, `Approval`, or `Site` entities; the `Observation` table is unused; AI candidate provenance and source regions are not persisted server-side or linked to measurements.
6. **Concurrency and deletion safety.** No optimistic locking on REST updates; hard deletes for customers, rooms, walls, and elements without tombstones; SQLite foreign keys disabled.
7. **AI controls.** `rate_limit_ai_per_minute` is unused; no idempotency keys for exports or Telegram sends; live provider unverified.
8. **Platform packaging.** `android/` and `web/` are generated and gitignored; no committed manifest, icons, or signing; mobile API host intentionally set to an invalid domain; APK/AAB unverified at current head.
9. **Export limits.** Only the first room is exported; generation is synchronous; Persian font shaping and print scale unverified; no retention or cleanup of generated files.
10. **Telegram.** Live path unverified; single replica; at-least-once rather than exactly-once; documentation contradictory.
11. **Security and operations hygiene.** Unencrypted local data, no malware scan, no TLS or proxy configuration, no lockfiles, no backend lint/type gate, weak health check.

## 7. Prioritized recommendations

### P0 — before any merge

1. Replace the `networkidle` wait in `scripts/browser_acceptance.py` with a deterministic readiness signal (app-emitted ready flag or a specific selector), then rerun the full client pipeline including APK/AAB.
2. Revert the autonomous-phase changes in `AGENTS.md` and `docs/development-roadmap.md`, or obtain explicit approval for that process change.
3. Remove auto-approval of manual walls/elements. Introduce explicit review/approval records and revision history for approved measurements; ensure exports exclude or flag elements with unknown dimensions.

### P1 — before a release candidate

4. Emit server-side audit events for sync edits, approvals, and conflict resolutions.
5. Add optimistic concurrency to REST updates, add tombstones or soft deletes, and enable SQLite foreign keys.
6. Enforce `rate_limit_ai_per_minute` and add idempotency keys for exports and Telegram sends.
7. Commit Android manifest, icons, and signing configuration, or document and verify a reproducible release pipeline; configure a real mobile API host.
8. Add dependency lockfiles and a backend lint/type-check CI gate.

### P2 — hardening

9. Encrypt local SQLite and photos; add upload malware scanning; bundle or document TLS and trusted-proxy configuration; add structured logging plus readiness and database health probes.
10. Extend exports beyond the first room; verify Persian shaping and print scale; add retention and cleanup.
11. Persist AI candidate provenance and implement the candidate-to-measurement import workflow; finish sketch crop, perspective, OCR, and voice capture.
12. Resolve the stale Telegram documentation contradiction and define a scaling approach beyond a single replica.

## 9. Conclusion

The reviewed branch contains a coherent implementation with a genuinely verified deterministic geometry core, solid session security, and meaningful automated coverage. It is **not release-ready**. The failing client CI gate, the auto-approval and in-place mutation of measurements, the absence of audit and revision history, and the unauthorized governance change in `AGENTS.md` are blocking issues.

**PR #1 must remain in draft and must not be merged** until the P0 items are resolved.
